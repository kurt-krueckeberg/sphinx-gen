The program will create new MyST Markdown files with the extension of `.md`, but it must NEVER overwrite,
truncate, rename, delete, or modify any existing Markdown file.

The program is configuration driven. A configuration file named
config.yml contains the input to build the .md files.

First, the program will read the config.yml file and load it into an array using a
programming language that supports such a function.

Using the array, it will then iterate these top-level keys:

- marriages
- baptims
- confirmations
- burials


## How the output ".md" file will be named

The MyST markdown output file's stem will start with "PET-". This will be
followed by the value of the `record-symbol:`, which is a single uppercase
letter; for example, the `record-symbol:` key under  `marriages:` is "M",
and for burials it is "D". Thus, the marriage MyST markdown files will
start with "PET-M" and the burial MyST Markdown files will start with
"PET-D". After these prescribed first five letters will come a "-". This
will be followed by a four-digit years, which is the last part of the value
of the "edate:" key. The value of "edate:" consists of a date in the form
of first the day of the month, followed by the name of the month, followed
by the four digit year; for example, in this `edate:` example snippet:

edate: 12 November 1675 

the year is 1675. If this "edate:" is a subkey of "marriages:", then the
output MyST markdown file stem will start with "PET-M-1675". IF it were a
subkey of "burials:", then the output file stem would start with "PET-D-1675".

Finally, after these first 10 characters of the file stem will come a single
lowercase letter. "a" will be used, if no such file stem exists; otherwise,
"b" will be used, if not such file stem exists; otherwise, "c" will be
used, if no such file stem exists. This will continue will the single
lowercase letter is selected. Let's take the prior example of "PET-M-1675".
If no file names `PET-M-1675a.md`, exists, this will be the new markdown
filename. If it does exist, the name will be `PET-M-1675b.md`, if no such
file exists. This process will continue until an file stem is
found that does not already exist for the current set of markdown files.

## Createing the Output file

The template below shows how the basic .md file content. Placeholder
variables are used to show how the values of the keys in config.yml map to 
the markdown output content.

Here is the ouput template:

````code
# %year% %name% %event%

## Record

The baptism of Hans Henrig from Peezen (Petzen) is on {ref}`image %image-no% <%file-name%>`
of the Petzen *%volume-name%*.

```{figure} images/%ifile%
:class: image-override
```

## Transliteration

```{div} doc-text
%literal%
```

## Translation

```{div} doc-text
%trans%
```

## Citation

(%file-name%)=

"Archion Protestant Kirchenbücher Portal", database 
with images, *Archion* (<%url%> : %vdate%), path: %path% > %parish% >
%volume-name%, image %image-no% of %total-images%
````

In the template above the variables that are delimited with '%' such as `%url%`
or `%trans%` represent keys in the config.yml; for example, `%trans%`
represents the values of the `trans:` key, and `%url%` represent the value
of the `url:`. The table below shows a more complete list of %-delimited
variables and the YAML keys they represent:

| key       | variable    |
|-----------|-------------|
| event     | %event%     |
| name:     | %name%      | 
| image-no: | %image-no%  |
| ifile:    | %ifile%     |
| edate:    | %edate%     |
| vdate:    | %vdate%     |
| url:      | %url%       |
| literal:  | %literal%   |
| trans:    | %trans%     |
